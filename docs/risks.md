# Residual risks and G02A-1 prerequisites

This is a local credential-free laboratory, not production security assurance. G01/G01-R/G01-R2 unresolved findings remain preserved. The assistant that implemented this core performed the subsequent read-only review, which returned FAIL with F01-F04. FIX-01 addresses those findings with regressions; this is not independent external assurance. Passing re-audit remains required.

| Risk / severity | Current limit | External closure required |

Uncontained routes from G01-R2: GitHub connector create/commit/ref/merge; local filesystem and shell execution; Sites/Vercel environment, credentials and deployment interfaces; Nexus GitHub source-write/publication/provisioning/onboarding; Google/Firebase credentials from environment/files/metadata, Firestore/Auth/Storage/Secret Manager/FCM; paid model/runtime API; signed remote management CRUD; Classroom LTI/grade/LRS/storage; Faroleiro encrypted scores/push; public contact delivery; browser/SEO/background workers and framework deployment outputs. Source/tool metadata does not establish actual live grants, and none was exercised or revoked here. A Guardian text rule cannot constrain those routes.

G02A-1 requires **separate authorization and independent review**, plus an externally prepared disposable offline VM with no host mounts/socket, secrets, network or production account access. The operator must own VM/supervisor, ingress and egress policy, project filesystem isolation and observation tools. Select matching maintained runtime/types; independently verify Node/SQLite/compiler/cache provenance and dependency advisories. Review signed root/policy custody and restricted canonicalization. Prepare process crash, simultaneous writer, stalled native execution, emergency ordering, file rollback and witness outage scenarios with externally recorded observers. Do not run hostile code or host/network escape attempts in this development environment.

FIX-01 also leaves UNKNOWN/DISPATCHING records pending indefinitely rather than inventing cancellation evidence. Cloning both ledger and witness duplicates the logical authority identity: deployment custody and clone prevention are external prerequisites. Two workers are tested as separate Guardian/SQLite connections in one process, not parallel operating-system processes. Synthetic provider acknowledgements cannot prove that a malicious adapter has no hidden effect.

FIX-02 addresses the re-audit's R01/R02 with bounded cached-context local STOP and exact boolean adapter acknowledgments. Cached context can be stale relative to another worker during outage; it permits only conservative local containment. Fence and pending incident are in memory until honest persistence succeeds and can be lost on process exit. The first incident is retained; this is not a durable incident queue or a distributed kill registry. No verified cache means no safe fallback authority. Asynchronous adapters are unsupported; fake cancellation responses do not prove real quiescence.

Current readiness: **FIX_02_READY_FOR_FOCUSED_INDEPENDENT_REAUDIT; G02A-0_CLOSURE_AND_G02A-1_BLOCKED_PENDING_PASSING_REAUDIT_AND_AUTHORIZATION; PRODUCTION_INTEGRATION_BLOCKED**. Required isolation/admin/audit/provider infrastructure has not been demonstrated. No deployed policy, real credential, live provider, paid model call, production permission change, autonomous agent communication or remote write was used.
