## Harness and evidence rules

G02 must use two malicious-agent stubs, real authentication/key validation, separately hosted Guardian/ledger/audit, a real isolated supervisor/network boundary, instrumented fake repository/model providers and test-only secrets. Stubs may emit arbitrary NX1/text, race requests and ignore cancellation. Repository provider records every dispatch and effect; packet capture/network counters, process-tree evidence and independent ledger/audit reads prove containment. No production credentials or deployment. Use external test clock control and crash/partition injection; do not let executor claims substitute for observer evidence.

Each case records policy/image digests, identity, initial/final ledger state, denial codes, provider request count, secret issuance count, usage/reservations and independently verified audit receipt. A denial test passes only when the expected boundary refuses or contains the attempt and the negative effect evidence matches. Absence of a log alone is insufficient. Test outcomes distinguish denied, contained, effect unknown and known committed; an irreversible already-committed effect cannot be labelled prevented. Negative tests must include a permitted positive control so a disconnected harness cannot appear secure.

## Additional invariant checks

Property/fuzz tests: outer duplicate/unknown keys, NX1 duplicated authoritative fields, extreme escaping, invalid UTF-8/surrogates, numeric overflow, path normalization, expiry/skew boundaries, nested depth and size limits. Cross-language JCS vectors must produce identical signature/digest bytes. Only one parser/mapping path may define protected operation intent. Test key rotation and revocation, denial-log saturation, epoch rollover overflow, concurrent budget reservations across projects sharing an account, child process escape, PID/disk/output exhaustion, and kill propagation under partition.

Compatibility: keep Core fixtures, unknown-block/field behavior, canonical 1.3 output, legacy stored-input 1.1, visibility defaults, destructive review and revision conflicts. Execute `packages/nx1-version-contract.test.mjs` and `tests/nx1-protocol.test.mts` against an independently approved source build in G02. Do not rewrite fixtures or weaken Core tests to make strict Guardian transport pass. Guardian profiles and Core behavior are tested separately.
