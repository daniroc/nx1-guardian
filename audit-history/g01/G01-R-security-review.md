## Distinct control boundaries

| Layer | What it can establish | What it cannot establish |
| --- | --- | --- |
| Protocol validation | Version, syntax, bounds, canonical parsing and proposal preview | Identity, user consent, rights or an actual execution limit |
| Guardian authorization | Current authenticated actor, exact intent/scope, policy/epoch, review and resource admission | Confinement of tools outside its gateway; semantic harmlessness |
| Capability enforcement | Gateway permits only current grant-bound adapter calls and credentials | Host isolation or future provider cancellation |
| Infrastructure isolation | VM, network/IAM/filesystem deny alternate and lateral routes | Correct policy or resistance to trusted-host compromise |
| Independent human administration | Enroll identities, sign/activate policy, approve releases/unlock, assign resources | Safety merely from readable text, an agent promise or two agreeing agents |

These are separate mechanisms and separate test claims. A textual instruction to use Guardian, a frontend button hiding a capability or this audit's compliance is not an enforcement boundary.

## Concrete administrative and credential requirements

Use a standalone repository and service under external ownership. Agent-produced code is untrusted development input; agents cannot release it, edit the active binary/configuration, own CI deployment secrets, alter trust roots or administer service IAM. External reviewers promote a pinned reviewed artifact to a separately administered host. Separate external roles: identity registrar, policy approver, release operator, emergency stopper, recovery approvers, audit reader/verifier and credential issuer; minimize shared root administration.

Admin login must require phishing-resistant MFA with hardware-backed authenticator plus local activation factor, on an admin-only origin from an external device/profile inaccessible to agents. Check authenticated issuer/audience/subject, assigned role, fresh step-up evidence and session expiry server-side; never trust a body field claiming MFA. Design references [NIST SP 800-63B-4](https://pages.nist.gov/800-63-4/sp800-63b.html) for authentication concepts; no deployed AAL compliance is claimed. Reject approval embedded in logs, prompts, screenshots or tool output. Admin web actions also require CSRF/origin defenses and clickjacking protection; tainted content is displayed safely and cannot run scripts or navigate the approval surface.

Two distinct externally enrolled subjects approve the exact policy digest/version, previous epoch, target deployment/account, limits, expiry and change purpose. A signer in external KMS/HSM signs only verified dual-approved manifests; no agent-to-signer route exists. Code author and release/policy reviewer are separate. Store approver evidence independently. Operator may stop immediately; unlock/key enrollment/recovery requires dual approval. Lost MFA or signer compromise causes durable lock, independent identity re-verification, session/key revocation, witnessed epoch reconciliation and re-enrollment; no chat-based recovery, shared recovery codes in agent home or agent-mediated emergency override. Two independent humans/roles are an external prerequisite; if unavailable, the system remains locked rather than silently replacing one with an agent.

Executor receives only a short-lived synthetic or gateway-session credential; provider credentials belong to external issuer/gateway. Project A credentials, identifiers, mounts, caches, sessions and results must not select or access project B. Administrative and audit credentials never enter workloads. Direct provider credentials stay disabled in the minimal plan: a coarse provider token cannot become a narrow branch/path permission just because the request contains those fields.

## Contract and consistency defects to resolve before implementation

F09 (high): bootstrap ambiguity. G01 envelope requires an externally allocated execution ID and budgetReservationId on all kinds, while execution sequence allocates them during admission. Specify a separate session registration step and per-kind closed schemas: proposal references a registered session, carries no authoritative reservation/grant; Guardian decision allocates execution/reservation; result can only reference them. Initial externally authenticated session initiation is a distinct non-agent control interface. Sign domain/schema/kind, key ID and canonical body consistently with a pinned registry. Proposal signature identifies the untrusted sender, never an administrative signer.

F10 (critical): kill/dispatch linearization. Independent kill and operation registries cannot provide an unspecified cross-store atomic stop. Gateway must stop taking new dispatch leases as soon as durable kill is observed; stop control fences/waits for outstanding dispatch leases or labels them in-flight. Define STOP_DURABLE as persisted lock; STOP_ENFORCED only when relevant gateways/supervisors confirm fencing; STOP_UNCONFIRMED if persistence fails. A provider call accepted before the fence may commit after stop. G01 A11 phrase 'zero new ... effects after fencing' must mean no newly authorized dispatches, not no late external commits. Test the precise race with barriers and external observers. A diagram omission is documentation inconsistency, not proof the kill registry exists.

F11 (high): global suspension versus exhausted-session state. G01 diagram combines dependency outage and budget exhaustion in SUSPENDED while prose allows only verified dependency auto-recovery. Separate service availability/lock state from per-session terminal budget state. Recovery of dependencies must never reactivate an exhausted session or return uncertain reservations. Give explicit clock, ledger integrity and telemetry denial predicates.

F12 (critical): compromised trusted dependency. A18 mostly verifies unsigned/substituted artifacts; it does not establish security when an approved Guardian, signer, gateway, ledger or identity service lies. Independent gateway hard ceilings, key custody, witnessed epochs and supervisor kill reduce accidental/faulty-component impact; none universally defeats a colluding compromised enforcement TCB. Declare loss of assurance, lock via independent operator path and rebuild/reconcile externally. Add dependency-fault injections and explicit unmitigated cases rather than returning PASS.

F13 (high): audit admission must use a current durable receipt for the specific decision/dispatch intent, not a stale healthy-sink flag or an earlier session receipt. No dispatch while outbox backlog/retention integrity is unknown. Emergency lock/revoke must remain possible without the ordinary sink, with separately durable kill event. If that emergency store also fails, admit nothing and report unconfirmed stop/termination honestly.
