## Minimal credential-free G02A

Goal: independently test deterministic admission, replay/budgets, fail-closed states and restart/kill semantics against two malicious-agent stubs. No live ChatGPT/Codex inter-agent messages, provider SDK calls, real repository writes, deployment, cloud identities or production secrets. Non-read effects exist only as fake-provider counter fixtures for replay/unknown-outcome tests and are never exposed as a real operation capability.

The externally prepared lab is a disposable local VM outside Nexus with networking physically/host-policy disabled except a private test network between fixture processes. No host home/shared workspace, credential mounts, metadata, SSH agent, browser cookies, Docker socket, Git remote or automatic hosting link. Clone/import only a reviewed inert bundle; no hooks, lifecycle scripts or arbitrary repository builds. The development assistant may edit proposed source but cannot promote it to an active trusted service; a human lab operator reviews and imports each digest. Same-host users/ACLs do not establish independence from a malicious host administrator, which remains an explicit test limitation.

Lab roles: two adversarial workload users; separate Guardian/gateway/ledger users; externally owned supervisor/kill process; synthetic admin tool launched by the operator outside agent workloads; independent audit writer/witness/observer with readback access. Generate local test-only keys and opaque credentials that have no acceptance outside the lab, label every artifact SYNTHETIC, and prohibit real account/config import. Cryptographic validation is real; MFA, provider behavior, cloud IAM and retention-lock are simulated. No privileged machine provisioning or permission changes happen during G01-R.

Allowlist is deliberately smaller than original G02: `repository.read_snapshot`, `proposal.preview`, `artifact.read`. `session.deliver` uses only bounded stub fixtures, no autonomous real agent communication. `sandbox.check` stays disabled until the human lab owner separately enables a fixed credential-free fixture; it never runs unreviewed code on the current Nexus host. Per-kind schemas and session registration are finalized as test-only contract refinements under F09, without editing Core or original G01.

Proposed artificial per-run caps for external approval: 4 stub iterations, 16 gateway/tool admissions including retries, concurrency 1 executor, job wall-clock 10 seconds, session wall-clock 60 seconds, 65,536-byte envelope/32,768-byte payload ceilings as in G01, 2,048 simulated token units and 100 integer synthetic monetary units at a fixed test price. Also cap ingress to 32 attempts per session per 60-second window with queue depth 16; over-limit attempts aggregate into bounded denial counters. Account/session/project aggregate caps are the same fixture hierarchy for deterministic tests. These values are test proposals, not user subscription quotas or active policy. Output bytes/process/memory/disk ceilings are set externally before hostile execution; missing physical limits deny that stage. The fake provider has no real model calls or fees, so real model tokens/spend are N/A. Agent-reported MET cannot update authoritative counters.

## Stages and authorization gates

1. G02A-0, after explicit user authorization: resolve F09/F10/F11/F13 in a test-only contract/ADR, prepare inert reusable code and unit/property tests in a standalone local project. Select supported runtime APIs and minimal pinned dependencies using official support evidence; use pnpm with frozen lock and lifecycle scripts disabled or externally reviewed. Do not install/provision now. Never claim Node range alone guarantees long-term support.
2. G02A-1: human operator reviews bundle/digests and supplies disposable offline lab, synthetic keys/policy/roles, fixed caps, separate audit/observer and denied host routes. If absent, stop at unit-level development; no hostile host execution and no approval inference from elapsed time.
3. G02A-2: run A01–A26 with positive controls and explicit simulated/not-applicable labels. Auth/MFA/provider/immutable-storage production guarantees remain NOT_VERIFIED. Kill/replay/fail-closed enforcement claims need real lab process/network/ledger observer evidence, not mocks alone.
4. G02A-3: external reviewer checks artifacts, limits and residual risks; accepts only the tested lab properties. Publish no service and create no real integration automatically. G02B requires new explicit authorization and B01–B08 production closure evidence.

Required independent artifacts: policy/schema/service digests, synthetic actor and role evidence, test input/result manifests, ordered ledger/kill states, durable decision receipts, host/network process observations, reservations before/after, fake provider dispatch/effect/usage log, audit/witness integrity report and uncertainty classification. Retain synthetic run evidence under operator-approved bounded local retention; G01's proposed production retention remains unapproved.

## Acceptance and stop conditions

G01-R documentation acceptance is met when all eight review areas have repository/tool evidence, B01–B08 include concrete external solutions/prerequisites/verifiers/residuals, A01–A18 are reviewed and A19–A26 cover missing routes/dependencies, and G02A is specified without any real provider credential or production access. This result is REVIEW_COMPLETE_WITH_CRITICAL_FINDINGS, never SECURITY_PASS.

G02A test acceptance requires exact intent/identity/version binding; no grant from untrusted admin claims; duplicate dispatch prevention under the fake-provider contract; aggregate cap invariants; correct uncertainty retention; no project lateral access; durable lock across restart; no newly authorized dispatch after fence; independently verified audit records; and explicit simulation limitations. A failed positive control invalidates the corresponding denial result.

Stop immediately on real credential discovery/import, an attempted real endpoint/deployment, reachable host/private/metadata network, agent-controlled active policy or lab supervisor, missing admission budget, unknown dependency/image provenance, unconfirmed kill interpreted as success, ledger divergence, missing audit receipt or evidence fabrication. Preserve artifacts, deny new work and require external recovery. No agent can authorize resume or an increased cap. Compromise of the lab's trusted host/Guardian/gateway is reported ASSURANCE_LOST; rebuilding and key reconciliation are external actions.
